# Objective mastery, focused practice and spaced revision

## Purpose

Connect verified lesson quiz outcomes to the next useful learning action without generating unsupported instructional material. This is a deterministic retrieval-practice loop, not an AI diagnosis or a claim of durable mastery.

## Evidence model

- Quiz correctness is calculated by the server from the stored lesson answer key.
- Objective links are read from the stored lesson quiz definition; clients cannot submit objective scores or change objective mappings.
- Each attempt stores bounded question indexes and objective-level correct/total evidence in the existing 30-attempt history.
- Objective mastery aggregates the available history: mastered at 80%+, developing at 50–79%, and needs review below 50%.
- Focused attempts contribute to objective evidence and attempt counts, but do not change the lesson-wide best score or lesson mastery level.
- Legacy attempts without question indexes remain readable as full-lesson attempts.

## Focused practice

A learner can start a focused practice set from a developing or needs-review objective. The runtime selects only existing quiz questions whose stored `objectiveIds` contain that objective. The server validates that requested question indexes are unique, integer, in-range and bounded, then grades the selected subset using the stored answer key.

No questions or explanations are generated by the revision workflow. If no linked quiz question exists, the runtime recommends reviewing the lesson explanation instead.

## Spaced review intervals

The review date is derived from the latest verified attempt for each objective:

| Latest objective accuracy | Suggested interval |
|---|---:|
| Below 50% | 1 day |
| 50–79% | 3 days |
| 80–89% | 7 days |
| 90–100% | 14 days |

The authenticated `GET /api/learning-progress` response exposes a bounded review queue across the learner's saved progress records. The Quick Revision Hub shows due and scheduled objectives. Dates are derived from the latest attempt rather than stored as a second source of truth, so no background worker or cron service is required.

## Safeguards and limitations

- Progress remains scoped to the authenticated user.
- Lesson access remains restricted to the owner or a published lesson.
- The queue is based on quiz evidence only; it does not imply code execution, independent problem solving, transfer, or long-term retention.
- The intervals are transparent deterministic defaults, not a scientifically calibrated or personalized spaced-repetition model.
- The queue only includes objectives that have objective-linked quiz evidence.
- This increment does not create fresh questions, send notifications, or deploy infrastructure.

## Validation

Tests cover question-index bounds and uniqueness, focused scoring, objective aggregation, interval selection, overdue status, and schema persistence. CI remains the acceptance gate for the full application build and security/curriculum checks.
